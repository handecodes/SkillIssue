# ADR-003: Real mined bugs over generated challenges

**Status:** Accepted

## Context

The challenge set is the product. The quality and authenticity of the bugs determine whether the app is worth using. Options considered:

- Generate bugs with a language model
- Write synthetic bugs manually, each designed to teach a concept
- Source bugs from real fix commits in open-source .NET repositories

## Decision

Source all bugs from real fix commits in MIT, Apache 2.0, or BSD-licensed .NET repositories. Each bug must meet the following criteria:

- A real failing test in the upstream repo that verifies the fix
- A symptom description that does not point to the location of the bug
- Three tiered hints (nudge, area, file and line) that are the only place the location appears
- Attribution to the original commit

GPL and copyleft licenses are excluded. AutoMapper was rejected on this basis.

## Consequences

**Accepted trade-offs:**

Sourcing is manual and slow. Finding a bug that meets the quality bar (isolated fix, misleading symptom, navigable but not obvious) takes research. The library grows incrementally.

License vetting is required for every new repo. This cannot be automated safely.

Not every good bug has a clean failing test. Some fixes are verified by integration or regression tests that are hard to point to precisely.

Difficulty ratings are subjective. What is hard to find for one person may not be for another.

**Benefits:**

The bugs are real and have passed code review in production codebases. The symptom is what someone would actually encounter.

The test infrastructure already exists in the upstream repo. There is nothing to maintain on the challenge side.

Students interact with real codebases and real test suites.
