# ADR-005: GitHub OAuth as the only authentication method

**Status:** Accepted

## Context

The app needs user accounts to track progress and associate fork submissions with a user. Options considered:

- Email and password with a custom auth implementation
- OAuth with multiple providers (Google, GitHub, Microsoft)
- GitHub OAuth only

## Decision

Use GitHub OAuth as the sole authentication method.

## Consequences

**Accepted trade-offs:**

Users without a GitHub account cannot log in. This is a real exclusion. The assumption is that the target audience (developers practicing debugging on real .NET repos) overwhelmingly has GitHub accounts.

GitHub is a third-party dependency for authentication. A GitHub outage affects all logins. There is no fallback.

If GitHub deprecates or restricts its OAuth app capabilities, the auth flow breaks and requires rework.

**Benefits:**

No password storage, hashing, or reset flow. No email verification. The security surface around credential management is eliminated.

GitHub identity is coherent with the rest of the app. Fork verification already requires GitHub. The user's login and avatar are available from the OAuth token without a separate API call.

One auth path, one callback, one provider. Simpler to implement and audit.
